# Политика доступа к данным: матрица ролей

Роль берётся из поля `users.role` (enum `user_role`, значения `employee` и `admin`) после разрешения сессии.

## Основная матрица

| Ресурс / операция | Endpoint | `employee` | `admin` |
| --- | --- | --- | --- |
| Справочник сотрудников | `GET /api/users` | Да | Да |
| Пожелания: чтение всех | `GET /api/wishes` | Да | Да |
| Пожелания: создание | `POST /api/wishes` | Да | Да |
| Пожелания: редактирование | `PATCH /api/wishes/[id]` | Нет, `403` | Да |
| Сборы: чтение сумм | `GET /api/donations` | Да | Да |
| Журнал возвратов: чтение | `GET /api/donations` | Да | Да |
| Участие в сборе | `POST /api/donations` | Да | Да |
| Изменение суммы / возврат | `PATCH /api/donations/[id]` | Нет, `403` | Да |
| Отметка «подарок вручён» | `PATCH /api/donations/[id]/gift-status` | Нет, `403` | Да |
| Переписка: чтение списка веток | `GET /api/chats` | Только своя ветка | Все ветки |
| Переписка: отправка сообщения | `POST /api/chats/[userEmail]/messages` | Только в свою ветку, иначе `403` | В любую ветку |
| Переписка: отметка прочитанным | `POST /api/chats/[userEmail]/read` | Нет, `403` | Да |
| Вход в систему | Google OAuth 2.0 через `/api/auth/[...nextauth]` | Да | Да |
| Регистрация нового сотрудника | `POST /api/auth/register` (роль всегда `employee`) | Да | Да |

## Обобщённые правила

| Категория данных | Правило |
| --- | --- |
| Чтение | Доступно любому авторизованному пользователю: справочник, пожелания, суммы сборов, журнал изменений |
| Изменение финансов | Только `admin`: изменение суммы, оформление возврата, отметка о вручении подарка |
| Модерация контента | Только `admin`: редактирование текста пожеланий |
| Личная переписка сотрудника | Изолирована по email владельца ветки; сотрудник видит и пишет только в свою ветку |
| Переписка всех сотрудников | Доступна только `admin` |
| Служебные отметки переписки | Только `admin`: `read_by_admin` |

## Фильтрация выборки по роли

| Endpoint | Роль `admin` | Роль `employee` | Файл:строки |
| --- | --- | --- | --- |
| `GET /api/chats` | `listChatThreads()` — все ветки | `[getChatThread(user.email)]` — одна своя ветка | `app/api/chats/route.ts:12-16` |

Это единственный маршрут, где выборка данных зависит от роли. В остальных случаях фильтрация не применяется: `GET /api/wishes`, `GET /api/users`, `GET /api/donations` возвращают полные наборы данных для любой роли.

## Проверка владения ресурсом

| Endpoint | Условие запрета | Код | Файл:строки |
| --- | --- | --- | --- |
| `POST /api/chats/[userEmail]/messages` | пользователь не `admin` и `threadEmail !== user.email` | `403` | `app/api/chats/[userEmail]/messages/route.ts:16-19` |

Остальные маршруты проверяют только роль либо только факт входа. Отдельной проверки «это мой ресурс» для пожеланий и сборов нет: пожелания редактирует любой `admin`, а участие в сборе не привязано к владельцу записи `donations` (она идентифицируется по получателю подарка).

## Ограничения на уровне схемы БД

| Ограничение | Таблица | Файл:строка |
| --- | --- | --- |
| Роль только `employee` или `admin` | `users.role` (enum `user_role`) | `db/init/001_schema.sql:7,22` |
| Google subject уникален, когда задан | `users.google_sub` (`UNIQUE`, nullable) | `db/init/001_schema.sql:18` |
| Причина возврата только из двух значений | `donation_history.reason` (enum `refund_reason`) | `db/init/001_schema.sql:10,48` |
| Сумма сбора не может быть отрицательной | `donations.total_amount` (`CHECK >= 0`) | `db/init/001_schema.sql:38` |
| Суммы в журнале не могут быть отрицательными | `donation_history.previous_amount`, `new_amount` | `db/init/001_schema.sql:46-47` |
| Автор, получатель и администратор существуют | внешние ключи на `users(id)` | `db/init/001_schema.sql:27-28,37,44-45,55-56` |
